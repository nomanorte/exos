# Contribuir a EXOS

Se aceptan Issues y Pull Requests en el repositorio público. Antes de abrir un PR, comprueba
si ya existe una propuesta equivalente. Para un cambio grande, abre primero un Issue que
explique el problema y el resultado deseado; el responsable decide si entra en el producto.

Trabaja en una rama o fork y abre un PR hacia `main`. Explica qué cambia, por qué, cómo lo
comprobaste y si modifica datos, instrucciones o compatibilidad. Mantén los cambios
acotados. La CI ejecuta comprobaciones, pero no reemplaza la revisión humana. No incluyas
datos personales, secretos, historiales de alumnos ni contenido de programas privados.

Un Issue o PR no garantiza incorporación ni fecha de release. Se puede proponer una mejora
abiertamente; la publicación de una versión sigue siendo una decisión del mantenedor.
Para vulnerabilidades o filtraciones, sigue [SECURITY.md](SECURITY.md), no un Issue público.
